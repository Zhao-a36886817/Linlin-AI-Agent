# P13 — Plugin Runtime and SDK

**Status:** LOCKED  
**Type:** platform-runtime  
**Purpose:** Define a versioned, deny-by-default plugin contract and lifecycle.

## 1. Objective

Deliver only the bounded Plugin Runtime and SDK scope while preserving every accepted P0–P9 architecture, security, privacy, testing, and cross-platform boundary.

## 3. Allowed Work

- Plugin manifests, capability declarations and SDK contracts.
- Install, enable, disable and uninstall lifecycle.
- Compatibility and hostile-manifest tests.

## 4. Forbidden Work

- Arbitrary in-process code loading by default.
- Unsigned remote installation by default.
- Scheduler implementation.
- Work assigned to any later P stage.
- Advancing `.laes/CURRENT_PHASE.yaml` without the required gate.

## 5. Architecture Invariants

- Plugins receive only declared approved capabilities.
- Tools still execute through Tool Runtime.
- Workspace and credentials remain mediated.
- Provider, Tool, Workspace, and Credential Runtime boundaries remain intact.
- Windows, Linux, and macOS remain first-class targets.

## 6. Deliverables

- Phase contracts and implementation limited to the allowed scope.
- Tests and security evidence for each acceptance criterion.
- Required ADR/RFC updates approved before architectural implementation.
- `P13_COMPLETION_REPORT.md` with scope, root cause, changes, results, risks, rollback, and deviations.

## 7. Acceptance Criteria

- Invalid or excessive manifests are rejected.
- Disabled plugins expose no capabilities.
- Lifecycle and compatibility behavior is deterministic.
- P0–P12 regression validation remains green.
- No unrelated feature, framework replacement, or future-phase work is present.
