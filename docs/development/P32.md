# P32 — Conversation-Bound LLM Training

**Status:** READY  
**Type:** product-runtime  
**Authority:** Project Owner request, 2026-08-09

## Objective

Provide real, capability-detected LLM training jobs that can be created from a
conversation, remain visible in that same Chat view, expose selectable eligible
models, cancellation and actual metrics, and refresh status/charts every two
seconds.

## Product boundary

- Implement a bounded Training Runtime and engine contract.
- Implement real OpenAI-compatible fine-tuning protocol support through configured
  cloud providers and backend-only credentials.
- Detect local LoRA prerequisites and list local training only when the required
  training stack and trainable model weights are actually available.
- Never represent Ollama inference-only models, prompts, sleeps, or synthetic
  counters as weight training.

## Security constraints

- Training data is conversation-scoped and explicit; cloud upload requires a
  separate consent at job creation.
- Credentials remain behind Credential Store and are never returned to the UI,
  stored with jobs, logged, or added to datasets.
- Engines cannot accept arbitrary shell commands or filesystem paths.
- Dataset size, message count, polling, concurrent jobs, and retained metrics are
  bounded. Cancellation is explicit and idempotent.

## Acceptance Criteria

- Eligible engine/model choices are discovered truthfully.
- A conversation can create and display its own training jobs.
- Status and metric charts update at a two-second interval while active.
- Actual provider job state/metrics are normalized; no fabricated progress exists.
- Cloud jobs require explicit consent and use configured backend credentials.
- Complete API/security/regression/UI Gate passes.
