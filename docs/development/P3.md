# P3 — Tool Registry and Context Efficiency

**Status:** LOCKED  
**Type:** Runtime optimization  
**Purpose:** Reduce unnecessary tool-schema context while preserving correct Tool Runtime boundaries and existing tool capabilities.

## 1. Objective

Introduce a clear tool-registry/profile strategy so each agent/request receives only the tools it is authorized and likely to need.

Default core tool set SHOULD remain small, for example:

- calculator;
- list files;
- read file;
- write file;
- replace text;
- search files.

High-risk or specialized tools such as terminal, Git, RAG, Memory, or code-management tools MUST NOT be globally injected by default.

## 3. Allowed Work

- ToolManager/ToolRegistry organization;
- tool definitions/schema generation;
- tool profiles/capability groups;
- lazy registration or request-scoped exposure;
- tests for tool visibility and schema selection;
- minimal ToolLoop integration required to pass selected definitions.

## 4. Forbidden Work

- implementing new terminal/Git/RAG/Memory features;
- changing Workspace security policy;
- Provider redesign;
- deleting functioning tools merely to reduce context;
- exposing privileged tools globally by default;
- UI redesign.

## 5. Architecture Invariants

- Tool Runtime is the only execution layer;
- tool definitions and tool execution remain separate concerns;
- model-visible tool schemas are explicitly selected;
- lack of schema exposure does not delete the underlying registered capability.

## 6. Deliverables

- canonical Tool Registry behavior;
- small default/core tool profile;
- explicit specialized profiles or selection mechanism;
- regression tests for tool visibility, invocation lookup, and duplicate names.

## 7. Acceptance Criteria

- ordinary chat/tool requests do not receive every registered tool schema;
- specialized tools appear only when explicitly enabled/authorized;
- tool names are unique and deterministic;
- ToolLoop still executes valid calls correctly;
- schema/context reduction is measurable or at least directly observable in tests/logical assertions;
- P0-P2 validation remains green.
