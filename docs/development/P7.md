# P7 — Cross-Platform Dependency and Configuration Normalization

**Status:** LOCKED  
**Type:** Portability hardening  
**Purpose:** Make the Linlin Agent source/dependency/configuration baseline reproducible across Windows, Linux, and macOS without hard-coded machine paths.

## 1. Objective

Normalize Python/frontend dependency definitions, paths, configuration, and development commands so the source tree is portable and reproducible.

## 2. Required Reading

- `AI_COLLABORATION_CHARTER.md`
- `AGENTS.md`
- `docs/standards/Engineering_Standard.md`
- `docs/standards/Testing_Standard.md`
- `docs/standards/Cross_Platform_Standard.md`
- `docs/architecture/System_Architecture.md`
- this file
- accepted dependency/platform ADRs, if present

## 3. Allowed Work

- canonical backend dependency metadata such as `pyproject.toml`;
- clean `environment.yml` without machine-specific absolute `prefix`;
- lockfile normalization where supported by the chosen toolchain;
- frontend package/lock consistency;
- `pathlib`/environment/config-based path fixes;
- platform adapter isolation where truly OS-specific behavior is required;
- documented Windows PowerShell and POSIX-shell development commands;
- portability tests.

## 4. Forbidden Work

- Tauri installer/release packaging;
- Docker migration merely for convenience;
- replacing Conda, npm, Vite, FastAPI, React, or Tauri without approved RFC;
- adding machine-specific absolute paths;
- bundling credentials or runtime-generated files;
- broad feature development.

## 5. Architecture Invariants

- core Python code uses portable path/config abstractions;
- OS-specific behavior is isolated behind explicit adapters/utilities;
- project configuration never assumes a particular username, drive, or home path.

## 6. Deliverables

- canonical backend dependency specification;
- clean cross-platform Conda/environment definition if retained;
- consistent frontend dependency lock;
- documented supported development environments;
- removal of hard-coded machine paths from active code/config.

## 7. Acceptance Criteria

- no active project config contains `C:\...`, `D:\...`, `/home/<specific-user>/...`, or equivalent machine-bound paths;
- dependency files are UTF-8 and reproducible;
- Python and frontend build/test workflows remain operational;
- platform-specific code is isolated and justified;
- P0-P6 validation remains green.

## 8. Required Validation

```bash
python -m compileall app tests

python -m pytest tests -q
```

Frontend when present:

```bash

```

Use repository-correct package manager commands if the project has formally standardized on another lockfile/tool.

Report dependency/config changes, hard-coded paths removed, platform-specific adapters, tested OS/environment assumptions, modified files, tests/results, and remaining portability risks.
