# P34 — Visible Training Workspace and Local LoRA Runtime

**Status:** READY  
**Type:** product-runtime  
**Authority:** Project Owner request, 2026-08-09

## Objective

Make conversation-bound training unmissable and add a real, bounded local LoRA
runtime for explicitly registered local Hugging Face model weights.

## Constraints

- Training stays bound to the current Chat conversation and polls every two seconds.
- The training entry must remain visible at supported desktop and mobile widths.
- Local training accepts only model directories registered under the configured
  model root; client-supplied absolute paths and traversal are forbidden.
- Ollama/GGUF inference artifacts must not be presented as directly trainable LoRA weights.
- Local training is opt-in, bounded, cancellable, and writes adapters only to the
  configured training output root.
- Heavy training dependencies remain an explicit optional installation.
- Cloud credential and consent boundaries remain unchanged.

## Acceptance Criteria

- Chat has a prominent, responsive training control that cannot be pushed off-screen.
- Capabilities discover eligible local model directories and explain missing requirements.
- A user can choose a discovered local or cloud model from the same training panel.
- A real local LoRA job reports provider-generated or trainer-generated loss metrics,
  status, cancellation, and adapter output without fake percentages.
- One-click launcher exposes optional local-training dependency installation.
- Path traversal, unregistered models, missing consent, cross-conversation access,
  and secret leakage are covered by tests.
- Training tests, full backend regression, frontend build/lint, Cargo, launcher tests,
  policy checks, and responsive UI inspection pass.
