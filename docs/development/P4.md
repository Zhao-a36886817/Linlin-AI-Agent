# P4 — Workspace, Archive, Git, and Terminal Security Boundary

**Status:** LOCKED  
**Type:** Security hardening  
**Purpose:** Ensure file, archive, Git, and terminal operations cannot escape the authorized workspace or leak protected host state.

## 1. Objective

Make Workspace Runtime the enforced filesystem security boundary for all model-accessible file operations and establish safe defaults for privileged tools.

## 3. Allowed Work

- Workspace path resolution and sandbox validation;
- workspace file/search/archive operations;
- ZIP extraction validation;
- Git working-directory confinement;
- terminal working-directory confinement, timeout, environment filtering, and safe default-disable behavior;
- symlink/reparse-point escape prevention where platform semantics require it;
- security regression tests.

Workspace internals MAY use `pathlib`, standard filesystem APIs, and OS-specific adapters as needed. Model-facing tools MUST NOT bypass the Workspace abstraction.

## 4. Forbidden Work

- enabling unrestricted shell execution by default;
- granting access outside the configured workspace;
- weakening path/symlink/archive validation to make tests pass;
- exposing host secrets/environment wholesale to commands;
- unrelated Provider/RAG/Memory feature work;
- broad UI changes.

## 5. Threat Cases That Must Be Covered

At minimum:

- `../` traversal;
- Windows-style `..\` traversal;
- absolute paths;
- drive/UNC paths where applicable;
- symlink/reparse-point escape;
- ZIP Slip/path traversal during extraction;
- terminal/Git `cwd` escape;
- unsafe archive overwrite behavior;
- secret-bearing environment inheritance where controllable.

## 6. Deliverables

- one canonical workspace-resolution boundary;
- security tests for path/archive escapes;
- Git/terminal confinement rules;
- terminal privileged capability disabled by default unless explicitly authorized.

## 7. Acceptance Criteria

- all model-facing filesystem tools resolve through Workspace Runtime;
- escape attempts fail safely and predictably;
- valid in-workspace operations continue to work;
- archive extraction cannot write outside destination root;
- terminal/Git cannot silently switch to an outside working directory;
- cross-platform path semantics are test-covered where feasible;
- P0-P3 validation remains green.
