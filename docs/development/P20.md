**Status:** LOCKED  
**Type:** release-engineering  
**Purpose:** Produce reproducible desktop packages with safe, signed update behavior.

## 1. Objective

Deliver only the bounded Desktop Packaging, Installer, and Auto-Update scope while preserving every accepted P0–P9 architecture, security, privacy, testing, and cross-platform boundary.

## 3. Allowed Work

- Tauri packaging for supported platforms.
- Installer, uninstall and rollback behavior.
- Signed update metadata and offline validation.

## 4. Forbidden Work

- Unsigned automatic updates.
- Embedding credentials in packages.
- CI/CD redesign.
- Work assigned to any later P stage.
- Advancing `.laes/CURRENT_PHASE.yaml` without the required gate.

## 5. Architecture Invariants

- Frontend remains the single UI source.
- Updates verify authenticity before installation.
- User data is preserved or explicitly migrated.
- Provider, Tool, Workspace, and Credential Runtime boundaries remain intact.
- Windows, Linux, and macOS remain first-class targets.

## 6. Deliverables

- Phase contracts and implementation limited to the allowed scope.
- Tests and security evidence for each acceptance criterion.
- Required ADR/RFC updates approved before architectural implementation.
- `P20_COMPLETION_REPORT.md` with scope, root cause, changes, results, risks, rollback, and deviations.

## 7. Acceptance Criteria

- Supported package checks are reproducible.
- Tampered updates are rejected.
- Install, update, rollback and uninstall paths are documented.
- P0–P19 regression validation remains green.
- No unrelated feature, framework replacement, or future-phase work is present.
