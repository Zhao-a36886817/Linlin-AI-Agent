# P25 — Commercial Runtime Control Center

**Status:** READY  
**Type:** product-integration  
**Authority:** Project Owner roadmap amendment, 2026-08-09

## Objective

Provide one polished, production-oriented control center for the already implemented Memory, RAG, MCP, multi-agent orchestration, and scheduler runtimes without moving runtime logic into the frontend or weakening existing security boundaries.

## Allowed Work

- Versioned API facades that expose existing runtime status and bounded operations.
- A single responsive React control center with clear navigation and empty/error/loading states.
- Memory list/create/delete controls with explicit consent and owner/session scoping.
- RAG ingestion/retrieval controls with workspace-safe paths and citations.
- MCP server/capability controls that remain deny-by-default and require explicit permissions.
- Multi-agent run controls with bounded depth, concurrency, budgets, cancellation, and visible status.
- Scheduler create/list/cancel controls for approved actions with confirmation and audit visibility.
- UI/API contract, authorization, redaction, accessibility, and regression tests.

## Forbidden Work

- Rewriting Memory, RAG, MCP, scheduler, orchestration, provider, tool, workspace, or credential runtimes.
- Returning secrets or credential material to the frontend.
- Enabling remote MCP, persistent memory, unattended jobs, or multi-agent execution by default.
- Arbitrary shell execution, unrestricted filesystem access, hidden cloud upload, or destructive operations without confirmation.
- Unrelated feature work, framework replacement, or modification of the nested `Linlin-Agent` copy.

## Acceptance Criteria

- One browser window provides Chat and all five advanced-runtime control pages.
- Every runtime has discoverable status, disabled state, safe empty state, actionable errors, and confirmation for high-impact actions.
- API contracts validate inputs, preserve owner/session boundaries, redact secrets, and reject unsafe paths or unapproved capabilities.
- Keyboard navigation, responsive layout, contrast, and reduced-motion behavior are covered.
- Backend tests, frontend lint/build, desktop checks, and launcher smoke validation pass.
- A completion report and Supervisor review package provide exact evidence.
